# v0.5 — Graph-Depth Off a Clean, Measured Base — Design Spec

**Date:** 2026-07-02
**Status:** Design (approved at high level; deep design pending user review)
**Predecessor:** the 30-day pipe-hardening plan (`docs/strategy/30-day-pipe-hardening-plan-2026-07-02.md`) — closed with the moat at 28/28 families built, 54% measured on the comprehensive fixture, dormancy closed (fixture → real agent `run()` → shared graph → report card, proven in CI).

## 1. Premise & North Star tie-in

North Star: _"Connect a cloud account → within minutes see your top ~10 real attack paths, prioritized, with a fix, at ~50–60% of Wiz value."_ The moat is the Security Graph (correlation into attack paths), not the commodity scanners.

The 30-day plan made the pipe **real, measured, and complete in breadth**. v0.5 makes it **deeper**: the three depth items that plan explicitly deferred. Sequenced **moat-first** — the two items that improve the prioritized output (the "top 10 that _matter_" promise) come before the commodity plumbing.

## 2. Scope

Exactly three items. Moat-first order:

1. **Probabilistic ranking** — replace the deterministic exploitability score with a belief-network + expected-loss ranking. (Biggest moat gain.)
2. **Real-graph depth benchmark** — resolve the NEX-203 deferral: does raising the generic walker past depth 4 pay for its noise/cost? Decide with measured numbers.
3. **Live readers** — the `NEXUS_LIVE_*`-gated readers the plan kept deferring. Build + wire + gated CI e2e; the operator runs the live lane.

### Non-goals (YAGNI — explicitly excluded)

- **No CPT-fitting / loopy belief propagation.** We have no labeled outcome data; hand-invented conditional-probability tables would be false precision. The belief network is the noisy-OR form only (§4).
- **No `NAMED_PATH_SIGNATURE` table.** Named archetypes already carry a curated severity; a parallel per-archetype edge chain would just drift against the detectors (§4.3).
- **No Neo4j / substrate swap.** Only a _possible_ v0.6 trigger the depth benchmark might surface (§5.3).
- **No catalog growth** (stays 28 families) and **no remediation depth** (path→fix hint stays as-is).
- **No new datastore, no new agent.**

## 3. Global constraints (bind every task)

- **Privacy contract (P0):** classifiers/evidence return a LABEL only, never the matched substring. The only approved plaintext exception remains the AWS access key ID (AKIA/ASIA). Non-AWS credential convergence uses `secret_fingerprint` (hashed).
- **"Done = I watched it work":** every detector/ranking change lands with a CI test that actually executes it against a realistic fixture. No live cloud access; `NEXUS_LIVE_*` lanes are operator-run.
- **Regression lock:** `packages/integration/src/fleet_testkit/REGRESSION_LOCK.md` (the 16-test green-path suite) stays green after every task.
- **commitlint:** lowercase subject, body lines ≤100 chars.
- **Honesty / no lipstick:** where a number is an expert prior, label it as such; where "done" is split (built vs operator-run), say so.

## 4. Item 1 — Probabilistic ranking (belief network + expected loss)

### 4.1 Current state

[report_card.py](../../../packages/agents/meta-harness/src/meta_harness/report_card.py) ranks by a deterministic score:

```python
def _exploitability(severity: int, path_type: str, *, kev: bool) -> int:
    return severity + (15 if kev else 0) + (8 if path_type in _INTERNET_FACING else 0)
# sort key: (-_exploitability(r[0], r[1], kev=r[5]), -r[0], r[2])
```

`blast_radius` is already computed (distinct data stores a path's principal can reach, via `find_fine_grained_data_exposure`). Two path sources merge into the ranked rows:

- **Named** (`AttackPathRanker.find_all`) → `AttackPath(path_type, severity, title, entities, evidence, count)`. **No edge chain, no explicit sink.** `entities` is a flat sorted tuple; named rows pass `kev=False`.
- **Generic** (`find_candidate_paths`) → `GenericPath` which **does** expose `source_id`, `sink_id`, `edge_signature`, `node_ids`, `sink_kev`, `sink_severity`, `sink_data_type`.

### 4.2 Target: three small pieces + two minimal edits

**New file `packages/agents/meta-harness/src/meta_harness/path_priors.py`** — the honesty boundary lives here.

```python
"""v0.5 — priors for probabilistic attack-path ranking.

Two prior sources, kept separate by how defensible each is:
- leaf_probability: MEASURED signals. EPSS is a published P(exploit-in-30d); CVSS
  severity + CISA KEV are public. A live EPSS reader (Item 3) feeds here later.
- EDGE_TRAVERSAL_PRIOR: EXPERT priors — hand-chosen P(traverse edge | source owned),
  one source of truth, TUNABLE, never presented as measured.

belief.py composes these; report_card ranks on the result.
"""
from __future__ import annotations

_KEV_FLOOR = 0.9  # CISA KEV = weaponized in the wild -> P floored here via noisy-OR

def leaf_probability(severity_score: int, *, kev: bool = False, epss: float | None = None) -> float:
    """P(the entry exposure is exploited). EPSS wins if present (already a probability);
    else the 0-100 severity maps linearly into [0, 0.8]; KEV floors at 0.9."""
    if epss is not None:
        p = float(epss)
    else:
        p = max(0, min(100, severity_score)) / 100.0 * 0.8
    if kev:
        p = 1.0 - (1.0 - p) * (1.0 - _KEV_FLOOR)
    return max(0.0, min(1.0, p))

# P(attacker traverses this edge | source already compromised). EXPERT priors, TUNABLE.
# Seeded from path_engine._EDGE_RISK, but these compose as a PRODUCT along a path (each hop an
# independent step), NOT the candidate scorer's weakest-link min.
EDGE_TRAVERSAL_PRIOR: dict[str, float] = {
    "EXPOSES_DATA": 1.0, "VULNERABLE_TO": 0.7, "RUNS_IMAGE": 0.95, "ASSUMES": 0.9,
    "HAS_ACCESS_TO": 0.85, "CAN_ESCALATE_TO": 0.9, "OWNS": 0.95, "OWNED_BY": 0.9,
    "DEFINED_IN": 0.8, "CAN_REACH": 0.6, "POD_CAN_REACH": 0.6, "PEERED_WITH": 0.5,
    "COMMUNICATES_WITH": 0.7, "CONTAINS": 0.8, "CONTAINS_PACKAGE": 0.4, "BINDS": 0.9,
    "EXPOSES_MODEL": 0.9, "EXECUTED_ON": 0.95, "MATCHES_INDICATOR": 1.0,
    "DEPLOYED_VIA": 0.7, "USES_SERVICE_ACCOUNT": 0.8, "IRSA_MAPPING": 0.8, "STORES_SECRET": 0.7,
}
DEFAULT_EDGE_PRIOR = 0.5  # unknown edge: coin-flip, never a silent 1.0
```

**New file `packages/agents/meta-harness/src/meta_harness/belief.py`** — the belief-network piece.

```python
"""v0.5 — noisy-OR belief propagation over extracted attack paths (the belief-network piece).

A sink reachable by multiple independent routes is more likely compromised than by any single
route. Attack paths are acyclic source->sink, so full loopy belief propagation / CPTs are
unnecessary: noisy-OR over the enumerated per-sink routes is the correct, ~20-line combination.

# ponytail: noisy-OR over enumerated source->sink routes; no CPT/loopy-BP engine — attack paths
# are acyclic. Upgrade only if cycles ever matter (they don't in this graph).
"""
from __future__ import annotations
from collections.abc import Iterable
from math import prod

from meta_harness.path_priors import DEFAULT_EDGE_PRIOR, EDGE_TRAVERSAL_PRIOR

def route_probability(entry_probability: float, edge_types: Iterable[str]) -> float:
    """P(this one route is walkable end-to-end) = entry leaf-prob x product of per-edge priors."""
    p = entry_probability
    for edge in edge_types:
        p *= EDGE_TRAVERSAL_PRIOR.get(edge, DEFAULT_EDGE_PRIOR)
    return p

def sink_probability(route_probabilities: Iterable[float]) -> float:
    """noisy-OR over every route reaching one sink: 1 - product(1 - p). More routes -> higher P."""
    return 1.0 - prod((1.0 - p) for p in route_probabilities)
```

**Edit `attack_paths.py`** — the _only_ change to the named ranker: add a sink so paths can be grouped for the noisy-OR.

- Add field `sink_id: str = ""` to `AttackPath`.
- In `find_all`, populate it per group: the `data_classification_id` where the archetype reaches data (it is already the last positional in the group's `.add(...)` entities for every data-reaching detector), else the primary resource/subject id, else `""`. Concretely, capture the sink when building each group (a parallel `sink_by_key: dict[tuple[str, tuple[str,...]], str]`) and pass it into the `AttackPath(...)` construction.

**Edit `report_card.py`** — swap the ranking function.

Data flow in `build_report_card`:

1. Build rows as today, but extend each row with its **sink id** and its **entry severity + kev**:
   - Named row sink = `ap.sink_id`; entry `leaf = leaf_probability(ap.severity, kev=False)`; `route_p = leaf` (named paths have no chain — severity already encodes archetype danger, §4.3).
   - Generic row sink = `cand.path.sink_id`; entry `leaf = leaf_probability(sev, kev=cand.path.sink_kev)` where `sev` is the row's severity; `route_p = route_probability(leaf, cand.path.edge_signature)`.
2. Group rows by non-empty `sink_id`; `sink_p = sink_probability(route_ps_for_that_sink)`. A row with empty `sink_id` is its own group (`sink_p = route_p`).
3. `expected_loss = sink_p * blast_radius`.
4. **Sort key = `(-expected_loss, -route_p, title)`.** Rows sharing a hot sink cluster at the right height, ordered among themselves by their own route probability.
5. Extend `AttackPathCard` with `probability: float = 0.0` (the card's own `route_p`) and `expected_loss: float = 0.0`. Keep `exploitability`/`severity` fields (back-compat; still rendered as secondary).
6. Render adds the probability + expected loss to the header/evidence line, e.g.
   `## 1. [P 0.76 · loss 3.8 · 5 stores] {title}` and keep `**Evidence:**` + `**Fix:**`.

`_exploitability` and `_INTERNET_FACING` are retained only if a test still needs them; otherwise delete (ponytail — expected-loss subsumes them). Decide at implementation: if nothing references them after the swap, remove.

### 4.3 Why named paths skip edge composition (rejected alternative)

A `NAMED_PATH_SIGNATURE: dict[str, tuple[str, ...]]` (a canonical edge chain per archetype) was considered so named paths could compose per-hop priors like generic ones. **Rejected:** each archetype's `severity` (60–95) is already the curated product judgment of that chain's danger, and a parallel edge table would be ~22 hand-maintained entries that silently drift from the detectors. Named path probability = `leaf_probability(severity)` is honest and zero-maintenance. Generic paths get full edge composition because they carry a _real_ `edge_signature` for free.

### 4.4 Honesty boundary

- **Measured:** `leaf_probability` inputs — EPSS (published), CVSS severity, CISA KEV.
- **Expert prior (labeled, tunable):** `EDGE_TRAVERSAL_PRIOR`. One source of truth; the docstring states it is not measured. A test asserts it is load-bearing (change the table → ranking moves) so it can never become dead config.

### 4.5 Testing (all execute in CI against fixtures)

- `test_noisy_or_combines_routes`: two routes to one sink → `sink_probability > max(individual route_p)`. **The belief-network property.**
- `test_route_probability_is_product`: a 2-edge route = `leaf × prior1 × prior2` (not min).
- `test_expected_loss_orders`: at equal `sink_p`, higher `blast_radius` ranks higher; at equal blast, higher `sink_p` ranks higher.
- `test_kev_dominates`: a KEV entry out-ranks an equal-structure non-KEV entry.
- `test_edge_prior_is_load_bearing`: mutating `EDGE_TRAVERSAL_PRIOR` changes the ranking (guards against dead config).
- `test_unknown_edge_uses_default`: an edge absent from the table contributes `DEFAULT_EDGE_PRIOR`, not 1.0.
- **Regression:** the comprehensive fixture (`test_coverage_comprehensive.py`) still renders a coherent top-10; `test_blast_radius_e2e.py` still passes (blast radius unchanged, now multiplied into `expected_loss`).

### 4.6 Done bar

Ranking runs in CI on the comprehensive fixture; a KEV + high-blast path visibly rises into the top-10; the belief/expected-loss tests are green; a data store reachable by ≥2 routes shows a higher `sink_p` than any single route.

## 5. Item 2 — Real-graph depth benchmark

### 5.1 Current state (two caps)

- `path_engine.DEFAULT_MAX_DEPTH = 4` — the generic walker's cap (passed to `store.walk_paths`).
- `charter.memory.semantic.MAX_TRAVERSAL_DEPTH = 3` — the substrate/kg_query cap (enforced by `_validate_depth` in `kg_query`, used by `attack_path`/`blast_radius`, **not** by the generic walker).

Because `find_generic_paths` already passes `max_depth=4` > 3 to `walk_paths` and works, `walk_paths` does **not** hard-enforce the 3-cap. NEX-203 deferred a _global_ bump to a real-graph benchmark measuring recursive-CTE cost + candidate-path noise as depth grows. Nobody has measured whether depth 5–6 pays off.

### 5.2 Target

**New: a synthetic dense-tenant generator + a sweep harness.**

`packages/integration/src/fleet_testkit/dense_tenant.py`:

```python
async def plant_dense_tenant(store, tenant, *, breadth: int, depth: int, noise: int) -> dict:
    """Plant `breadth` known source->sink chains of length `depth` (via the REAL agent writers where
    cheap, else direct upsert), plus `noise` dead-end branches that lengthen paths without reaching a
    sink. Returns {'planted_deep_paths': [...], 'node_count': N, 'edge_count': M} for recall scoring.
    Smallest generator that stresses the walker — not a general graph fuzzer (ponytail)."""
```

`packages/integration/src/fleet_testkit/tests/test_depth_benchmark.py` (or a `bench/` script — decide at plan time; a `pytest` that prints a table and asserts a floor keeps it in CI):

- Plant one dense tenant (e.g. breadth 20, depth 6, noise 200).
- Sweep `max_depth ∈ {4, 5, 6, 7}` over `find_generic_paths` / `find_candidate_paths`.
- Measure per depth: **(a)** wall-clock of the walk; **(b)** candidate-path count (noise proxy); **(c)** planted-deep-path recall (fraction of the known depth-5/6 chains surfaced); **(d)** novel-but-junk rate (candidates that are dead-end noise).
- Print the table; assert the harness runs and recall at the chosen cap ≥ a floor.

### 5.3 Deliverable = a measured decision

The output is **not** a blind bump. Options the numbers choose between:

- **Keep 4** (if 5–6 adds mostly noise for little recall).
- **Bump to N** (if recall gains clearly beat the cost/noise).
- **Adaptive cap** — depth shrinks as graph density rises to bound CTE cost (recommended shape _if_ cost grows non-linearly): `max_depth = f(node_count, edge_count)`.

**Substrate-cap dependency (possible v0.6 trigger):** if the benchmark shows the walker is CTE-cost-bound past some depth on realistic sizes, that — not a guess — is what would wake the parked Neo4j/substrate item into v0.6. Record the measured threshold either way.

### 5.4 Done bar

Benchmark executes in CI, prints a table of real numbers across depths 4–7, and a defended cap decision (keep / bump-to-N / adaptive) is landed as a one-line change to `DEFAULT_MAX_DEPTH` or a small `max_depth` helper, with the measured numbers cited in the commit.

## 6. Item 3 — Live readers (build + gate; operator runs the lane)

### 6.1 The deferred reader list

All `NEXUS_LIVE_*`-gated. Each maps a cloud SDK's model into an **existing** dataclass — the detectors are already provider-agnostic (proven by `test_reach_provider_agnostic.py`), so no detector changes:

| Reader              | Maps live source → existing dataclass                                | Detector it feeds                          |
| ------------------- | -------------------------------------------------------------------- | ------------------------------------------ |
| Azure NSG reach     | NSG rules + NIC ASGs → `NetworkInstance` / `SecurityGroup`           | `reach_grants`                             |
| GCP firewall reach  | firewall rules + instance tags → `NetworkInstance` / `SecurityGroup` | `reach_grants`                             |
| GCP SA-key IAM      | SA keys → `GcpServiceAccountKey`                                     | `sa_key_ownership`                         |
| Azure SP-secret IAM | service-principal secrets → the identity SP dataclass                | (identity escalation/ownership)            |
| Identity live feed  | live IAM listing → `IdentityListing`                                 | `identity.run(iam_listing=...)`            |
| AppSec live feed    | live secret scan → leaked key ids                                    | `appsec.run` → `record_leaked_credentials` |

### 6.2 Pattern (per reader)

Reuse the injectable-Protocol pattern already in [gcp_iam.py](../../../packages/agents/identity/src/identity/tools/gcp_iam.py) (`GcpIamReader` / `GcpIamLiveReader`):

1. A `Protocol` for the client (unit-testable without the cloud SDK).
2. A live reader class that maps raw SDK dicts → the existing dataclass tuple.
3. **No new deps** beyond the cloud SDK each agent already vendors.

### 6.3 Testing

- **Ungated composition test (runs in CI):** feed a _fake_ client returning realistic raw dicts → assert the reader produces the exact dataclass tuple the detector consumes. Proves the mapping without cloud access.
- **Gated live e2e (`NEXUS_LIVE_*`, skipped in CI):** the operator runs it against a real account.

### 6.4 Done bar (split, stated honestly)

- **My side:** each reader built + wired + ungated composition test green + gated e2e written.
- **Full:** the operator runs the gated lane against a real account. The report says exactly this — no lipstick that live is "proven" when only the mapping is CI-proven.

## 7. Sequencing & decomposition

Moat-first: **Item 1 → Item 2 → Item 3.** Items are independent enough that the implementation plan MAY split into three task-groups (or three plans). They share the regression lock and the honesty constraints. Recommendation: one plan, three clearly-grouped task sequences, each independently testable, regression lock green between every task.

## 8. Decisions log

- **D1** Named-path probability = `leaf_probability(severity)`, no edge composition, no `NAMED_PATH_SIGNATURE` (§4.3).
- **D2** Belief network = noisy-OR over enumerated per-sink routes; product (not min) edge composition; the candidate scorer's `_EDGE_RISK`/`score_path` is left untouched (separate concern).
- **D3** `AttackPath` gains only `sink_id`; grouping happens in `report_card`.
- **D4** Rank key = `(-expected_loss, -route_p, title)` where `expected_loss = sink_p × blast_radius`.
- **D5** Depth benchmark decides keep/bump/adaptive from measured numbers; substrate swap stays parked unless the benchmark proves a CTE-cost bound (v0.6 trigger).
- **D6** Live readers are build-and-gate; "done" is split and stated honestly.
